# Knot Atlas

Static site, generated by `python3 build.py`. Never hand-edit generated HTML
(`index.html`, `knots/`, `basics/`, `finder/`, `about/`, sitemap/robots/llms.txt).

## How a knot is made
1. Model in `geometry.py`: a function returning ropes (control points), optional
   `code` (over/under letters, one per crossing, read in traversal order: rope 0
   first, then rope 1; first visit of each crossing consumes a letter), objects
   (pole/ring), and `marks` (named control-point indices the steps reveal up to).
   Knots on objects are modelled in explicit 3D with `coil_y` / `coil_x` helpers.
2. Preview: `python3 tools/preview.py <geometry_fn> <outdir>` → PNG with numbered
   crossings plus a top view. Look at it before trusting a model.
3. Content in `knots.py` (steps reference marks). Step captions must match the
   tags the model produces: check with the tag dump snippet in progress.md.
4. `python3 build.py` runs the checker (rope/rope, rope/object clearance, crossing
   count vs code, and knot type via Jones polynomial where the knot has `expect`
   and the geometry has `closure`). Problems print as warnings; do not publish with warnings.
   The build first runs every `tests/check_*.py` (`tests/check_jones.py` proves the
   KNOWN table against PD codes / a braid for 8_18, and the link code on curves of
   known type); it stops if any fails (`--skip-tests` only for quick iterations).
   Topology fields per knot: `expect` (whole closure; a result with half powers of t
   is reported as an invalid closure: the joining arcs cross the drawing),
   `expect_each` (each rope alone), `expect_link` (`{'lk', 'jones'}` of rope 0 closed
   above everything and rope 1 closed below: the fixed closure rule in
   `knotlib.link_pair`; the linking number alone is closure-dependent, this rule is not).
   Record values with `python3 tools/invariants.py <slug>`. Where no published type
   exists, two independently drawn models must print the same invariants before a
   value is pinned. The state sum is practical up to ~22 crossings.
5. A clean checker is not proof of the right knot: the wave-1 Square Knot passed
   clearance but was topologically wrong. Give every knot that closes to a known
   type an `expect`, and compare tags per step with the captions.

## Conventions
- All text is original. Do not name or cite the reference book used for the knot
  syllabus anywhere in the project (code, docs, commits). The reference PDF lives
  outside the repo and is never committed.
- Rope colours: a = yellow (ochre), b = blue (teal), c = red (rust). Captions call
  them yellow/blue/red.
- English only. iPhone rules: 44px targets, 16px inputs, safe areas.
- three.js r128 from cdnjs + OrbitControls from jsDelivr, pinned.
- Headless Firefox screenshots do not capture WebGL. To check a 3D render, copy
  the canvas into an <img> via toDataURL in a throwaway page (see progress.md).

## Share pictures (og:image)
Added 2026-10-28. Every public page has a 1200×630 share picture at `og/<canonical path>.jpg` (`og/index.jpg` for the front page) and the tags `og:image` (+ width, height, alt), `twitter:card` = `summary_large_image` and `twitter:image`. `build.py` writes the tags (`og_tags()`), placed after the page's other og:/twitter: tags. The pictures are drawn by `engine/og_cards.py` in the followorbounce.github.io repo (one card template, this site's own palette and type, `og/manifest.json` = a hash per card so unchanged cards are skipped). After adding or renaming a page, or changing a title or description, run `python3 engine/og_cards.py knots` from that repo; it renders new cards, adds missing tags and deletes cards of pages that went away. `--check` lists pages without tags.

## Page weight (2026-10-28, reach plan F3)
The front page was 6 MB and the activity pages up to 2.8 MB because every card inlined a full knot drawing. Now:
- **Thumbnails are files**: `build.py` `thumb()` writes `assets/thumbs/<slug>.svg` and the cards use `<img loading="lazy">` with the drawing's width/height (no layout shift). An `<img>` doesn't see `site.css`, so each file carries the object colours (`THUMB_CSS`, light + `prefers-color-scheme: dark`); keep it in step with the `--wood`/`--metal` tokens. The share cards use these files too.
- **Smaller drawings** (`knotlib.svg_diagram`): rope pieces are `<path>` with relative coordinates in tenths of a pixel (`_path`, `_num`) and one class per stroke style in a `<style>` inside the drawing (class names carry rope colour + width, so drawings on one page share them safely); away from crossings and objects (`_crowded`: nothing else within 2.6 r) a rope stretch is one path instead of 5-point depth-sorted pieces (`_runs`). Crowded stretches keep the old 5-point pieces. **Merging is off by default (`merge=False`)**: the encoding alone renders pixel-identical drawings at 41% of the old bytes; merging reached 37% but shifted pixels in 378 of 438 drawings, not worth it on a site where crossings must read right. Pass `merge=True` only after a visual check.
